## 2026-09-06: the missing `Im(a_{L,1})` degree of freedom is restored (`k_L = 2L` → `2L+1`)

The largest known open defect is closed. `splittosingularalm` wrote
`complex(real, 0)` for `m == 0 or m == 1`, forcing `Im(a_{L,1}) = 0` at every
multipole, so the model carried 2L real dof where a real field on the sphere has
2L+1 and **could not represent a general sky** — 20% of the modes missing at
ℓ=2, 0.8% at ℓ=63. Only the `m == 0` case is correct (a real field's m=0
coefficient is real); m=1 shared the branch by accident.

Done as the staged plan in `docs/notes/restore_missing_alm_dof_scoping.md`
(Steps 1-5; that note's "What was actually done" section carries the full
detail). Suite green: 130 passed, 1 skipped, ruff clean.

**Production-scale validation, Step 6 of the scoping plan.** A single-realization
pilot at the exact job-11903181 configuration (lmax=64, `phi_mass_matrix='prior'`,
Block 4 OFF, MAP start; job 11951115, harvested 2026-09-08) passed all three
pass criteria: φ-power/truth ratio **0.9612** (O(1)), alm-vs-truth cosine
similarity **+0.9942** (high), `logp` plateaued (mean 26200.5 sweeps 0-299 vs
26198.0 sweeps 300-599, flat within noise). The restored packing samples
correctly at production scale. **This is not yet the exactness re-run itself**
— that is the 12-realization ensemble (job 11955622, launched 2026-09-08,
`results/analysis/coverage_ensemble_lmax64_prior_nocl4_packingv2/`), which
re-establishes (or revises) the headline pair φ 0.4688/alm 0.5312 (job
11903181, pre-restoration 2L packing) under the corrected model. See
`ROADMAP.md` for harvest instructions and status.

**What changed structurally.** `alm_utils.packed_sizes`/`packed_length` are now
the single definition of the `(n_real, n_imag)` split, and the 32 files that
carried the literal `(lmax-2)*(lmax-1)//2` inline derive from them instead.
`packed_dof_per_multipole` returns 2L+1 *because it counts the packing*, so
Blocks 1 and 4 moved without either inverse-Gamma conditional being edited by
hand — which is exactly what that function was written for on 2026-08-31.

**Two sites the scoping note's 276-site survey missed, both caught by tests:**

- `alm_utils.hpalminit` realified the first `2*lmax - 1` healpy entries, i.e.
  the m=0 **and** m=1 blocks. `model.py` calls it on the data alms and the prior
  alms, so the defect was imposed on the *inputs*, not only on the sampled
  vector. A grep for the packed-length literal could never have found it.
- `lensing.sample_phi_amplitude_rescale`'s acceptance ratio is packing-dependent:
  the Jacobian exponent is `n_L + 2 - k_L`, which is 1 when `n_L = k_L = 2L` and
  2 when both are 2L+1. **The brute-force test had `2L+2` hardcoded and so agreed
  with the code**; both were wrong together, and only
  `test_rescale_move_preserves_stationary_distribution_of_exact_gibbs_chain` —
  which compares against an independent exact-Gibbs reference chain rather than
  against the analytic expression — caught the shift in the ln C_2 marginal.
  **Standing lesson: an analytic reference that shares an assumption with the
  code is not independent.** This is the same failure mode as the 2026-08-31
  PIT that validated the draw but not the derivation.

**The new test that would have caught the original defect** is
`test_general_synalm_draw_survives_pack_unpack_with_no_power_loss`: an
unrestricted `hp.synalm` draw through pack→unpack, with exact per-multipole
power. A round-trip test alone never could — the restriction is idempotent, so
pack→unpack→pack was stable while silently lossy, exactly as with the
2026-08-24 ordering bug.

**Not established: that this fixes anything about sampling.** Step 0 of the plan
(measure that the missing mode tracks the low-ℓ pathology before spending the
effort) was skipped by decision. No evidence links it to the `[10,30)` strict
`C_L^φφ` residual or the chronic `[2,10)` R̂ problem.

**Invalidates every φ number recorded above.** All of them were measured through
the 2L packing. The pre-change reference to compare the re-run against is
φ 0.4688 (KS_p 0.124) / alm 0.5312 (KS_p 0.235), job 11903181. Checkpoints are
versioned (`samplers.PACKING_VERSION = 2`) and resume refuses on a version or
length mismatch, so the 107 pre-change checkpoints fail loudly instead of
resuming into a wrong-length vector.

- **Phase 1 — differentiable lensing operator**: gradients w.r.t. both alm and φ validated against finite differences and an independent gold-standard Jacobian.
- **Phase 1.5 — dense SHT matrix eliminated.** Matrix-free ducc0 SHT behind `tf.custom_gradient` (~500x under the speed gate; the dense path didn't fit in GPU memory). This is what makes lmax=300+ tractable at all.

Requires MAP initialisation before burn-in — without it, burn-in looks like unresolved drift even though the sampler itself is correct.
- **Phase 2 pre-production gates, both resolved.** (1) Joint (alm, φ) mixing at lmax≤50 is marginal, not pathological — HMC on both blocks needs no reparametrisation. (2) An unlensed-operator exact-Gaussian shortcut for alm|C_ℓ was **rejected** (652% worst fractional bias in C_l^TT — weak lensing isn't norm-preserving enough at this S/N). HMC-on-both-blocks is the production configuration.
- **Matrix-free port of the φ-block (Block 3) lensing operator — done, full-sky and masked-sky validated.** Full-sky matches the dense reference to numerical precision; masked-sky validated by finite differences directly on the matrix-free path (the dense path isn't a valid masked-sky reference at nonzero φ).
- **Beam transfer function + HEALPix pixel window — validated, opt-in** (`beam_fwhm_arcmin=None` on `CosmologyAdvancedSampling`, `None` = old behaviour). Validated against an independent ground truth (`healpy.almxfl`+`alm2map`).
- **Anisotropic per-pixel noise — validated, opt-in** (`noise_map=None`, `None` = old behaviour). Validated against an independent ground truth.
- **Block 4 — C_L^φφ|φ exact inverse-Gamma draw — validated, opt-in (`sample_cl_phiphi=True`).** Same exact-conjugacy argument as Block 1's C_ℓ|alm draw. Validated against a brute-force cross-check and a 3000-realization recovery test. Resamples the φ prior spectrum every sweep and rebuilds the φ mass matrix to match; mutually exclusive with `phi_mass_matrix='fisher'` (the guard on `'block'` was relaxed in `4f6eb74` by freezing only the expensive likelihood-curvature estimate and cheaply rebuilding the diagonal prior-precision term from the resampled spectrum each sweep; HMC leaves its target invariant for any *fixed* SPD mass matrix, so a frozen block matrix is exact, merely suboptimal). Full checkpoint save/resume support. **A PROPER conjugate prior is now available and is the recommended setting for any claim about the C_L^phiphi posterior (2026-08-31):** `sample_cl_phiphi_given_phi(..., prior_nu=nu, cl_phiphi_fid=...)` gives `C_L^phiphi|phi ~ InvGamma(k_L/2 + nu/2, (S_L+nu*C_L^fid)/2)` = `InvGamma(L + nu/2, ...)`, exposed on `run_gibbs_chain` as `cl_phiphi_prior_nu`. **nu>0 is enforced rather than advised** — the phi marginal tail is `r^(-1-nu)`, normalisable exactly above 0 (nu=0 still diverges logarithmically), so a value that left the target improper while appearing to fix it is rejected at the API. (This entry originally read `L-0.5+nu/2` and `nu>2`; both were corrected on 2026-08-31 with the dof fix below.) `prior_nu=None` is bit-identical to the old flat-prior path, RNG-stream consumption included. Two traps found while building it, both now guarded by tests: the prior's fiducial **must be snapshotted before the sweep loop** (`run_gibbs_chain` rebinds `cl_phiphi_full` every sweep, so centring the prior on the live value makes it chase the chain and exert no restoring force at all — while still passing every unit test of the conditional itself; caught by mutation testing, 6.82 e-folds above fiducial when chasing vs 4.72 when correct, flat-prior reference 6.76), and for the rank test to be valid the *truth* must be drawn from the same joint prior (`coverage_ensemble_chain.py --cl_phiphi_prior_nu` does this on a dedicated RNG stream). **Re-confirmed self-consistent end-to-end 2026-08-31 on production chains** (note: self-consistent, NOT exact — see the dof entry below for why this class of check cannot establish exactness): using the saved per-sweep (`phi_samples`, `cl_phiphi_samples`) pairs from job 11899585, `u = CDF_InvGamma(L-0.5, S_L(φ_i)/2)[C_{L,i}]` is uniform to **KS_p=0.53, mean 0.4970 over N=17856** (a deliberate lag-1 misalignment control degrades to KS_p=0.006, so the test had power **on that job**). ⚠ **On job 11903182 the same check is currently vacuous**: aligned KS_p=0.42 but the lag-1 control *also* passes at KS_p=0.183, because φ moves so little sweep-to-sweep under the Block-4-ON funnel that `S_L(φ_i) ≈ S_L(φ_{i+1})`. A PIT pass is evidence only when its deliberately-broken control fails — check the control every time. **But note the standing caveat: the implied flat prior on `C_L^φφ` is improper, and integrating it out leaves a φ marginal that is flat in `S_L` — improper and rising with amplitude** (marginal ∝ `S_L^{-(k_L/2-1)}` against the `k_L`-component measure `r^{k_L-1}dr` gives `p(r) ∝ r¹`; verified numerically, and robust to the dof convention — the `k_L` cancels, which is why this conclusion survived the shape-parameter correction). So with Block 4 on the φ amplitude is constrained by the likelihood alone, and an SBC rank test against a truth drawn from a *proper* `N(0, C_L^φφ,fid)` is not a valid calibration test. This is the same fact as the scale-free-prior entry below, stated as a marginal.
- **φ-block memory leak — root-caused and fixed at lmax=32** (eager `tf.py_function` calls leaking TF's process-global registry; fixed by tracing `bootstrap_results`+`one_step` together in `@tf.function`, ~20,000x RSS reduction). **Caveat: recurred at lmax=128** in a later coverage-pilot run (OOM after ~1200 sweeps) — fix holds at the scale validated, not confirmed to fully close the leak at production scale. Workaround: restart the process periodically.
- **lmax=300 point-validation run at `phi_n_lfs=80`: chain is healthy, φ-amplitude deficit is under-mixing, not sampler geometry.** Recovered φ power under-estimated by roughly half to seven-eighths across l=10-300; deficit decreases smoothly with S/N (Spearman ρ=-0.78) — the signature of an under-mixed start, not HMC correlation-length degradation. Same phenomenon as the lmax=128 stuck-bin finding below, at a different scale. Not being chased with further lmax=300 compute — resolving the φ-equilibration track (below) makes this moot.

## φ-block equilibration: root cause found and fixed (2026-08-17→18)

The central blocker for the whole project since lmax≈128 pilots began: the φ block (Block 3) fails a fixed equilibration gate (worst lag-1 autocorrelation < 0.9, worst drift < a few σ, phi accept ≥ 0.15) needed before the coverage/rank ensemble (the paper's headline exactness evidence) can be trusted. Every attempt below is a real, ruled-out hypothesis — don't retry without new evidence.

**Ruled out, in order tried:**
1. **Tuning axes (resolution, window length, trajectory length, integrator) — all NO-GO, none closes the gate.** phi_n_lfs 80→240→480 is non-monotonic (can regress a previously-passing bin); lengthening the window 3700→7000 sweeps buys marginal not qualitative improvement; dropping lmax 128→64→32 relocates the stuck bin rather than removing it. MCLMC (isokinetic leapfrog, `diffcmb/mclmc.py`) wins ESS/wall-clock-second at every probed bin but fails the actual equilibration gate twice (untuned and step-size-tuned), including one run where careful nside=128 step-size tuning made lag-1 autocorrelation *worse* (≈1.000 vs ≈0.975-0.99 untuned).
2. **Harmonic band-edge hypothesis — tested, falsified.** The stuck bin is not reliably the one nearest the lmax cutoff (a middle bin failed worse than the edge bin in a directly comparable lmax=128 run).
3. **Diagonal Fisher mass matrix (one-shot burn-in estimate) — NO-GO, and worse than no preconditioning** (worst lag-1 0.999, worst drift 7.19σ vs the plain run's numbers). Closed as unfavorable.

**Root cause, confirmed 2026-08-17 (job 11774832):** the φ-block posterior has significant **cross-L Hessian coupling** — perturbing a coordinate in one L-bin measurably changes the gradient in a different L-bin (mean coupling ratio 0.26-0.62 between distant bins, up to 0.97 at individual points). This is *comparable in magnitude* to the within-bin curvature a diagonal mass matrix captures. It explains every failure above: no diagonal-in-L preconditioner (prior-only or Fisher) can represent curvature that lives *between* L-bins.

**Fix implemented and unit-tested 2026-08-18: `phi_mass_matrix='block'`, a per-m-block Nystrom cross-L correction.**
- `lensing.py::estimate_phi_block_hessian` groups φ coordinates by (channel, m) — the same grouping used for the analogous alm Block-2 problem (`messenger.py::build_block_cholesky`, where same-m coupling was found to dominate; carried over as a plausible but not independently re-verified assumption for φ specifically — **if the block pilot below is NO-GO, check this assumption first**, via an m-resolved version of `diagnose_phi_hessian_coupling.py`). For each block, a low-rank Nystrom approximation of the true Hessian is built from a handful of single-coordinate FD gradient probes (the same validated FD method `estimate_phi_diag_fisher` uses).
- `samplers.py::build_phi_block_mass_chol`/`PhiWhitener` fold this into a per-block Cholesky whitening, one-time burn-in estimate (frozen thereafter, like `'fisher'`), mutually exclusive with Block 4.
- Two real bugs caught during testing: (1) a fixed absolute eigenvalue-clipping floor caused ~10^15x blow-up since curvature scale varies hugely across L — fixed with a scale-relative floor; (2) `tf.gather` produced ambiguous `IndexedSlices`/dense gradients inside TFP's traced leapfrog loop — fixed by forcing a dense gradient through `scatter_nd` (`samplers.py::_dense_grad_gather`, a reusable pattern for future preconditioning code). 9 new tests, full suite green (101 passed/1 skipped).
- `pilot_coverage_equilibration.py` gained `--phi_mass_matrix {prior,fisher,block}` (was hardcoded to `'prior'`+Block4-on) and forces Block 4 off automatically for `fisher`/`block`.

- **The coverage rank statistic is non-uniform for a correct sampler, and must be read against a simulated null (2026-08-31).** `aggregate_coverage_ranks.py` compares the truth's realized power `S_L/k_L` (`k_L = 2L` the packed dof) against posterior draws — but that is exactly the **mode** of the inverse-Gamma conditional, and an inverse-Gamma is right-skewed, so `P(draw < mode) < 0.5` by construction; bin-averaging over ℓ shrinks the spread while preserving the offset, so a naive uniformity test rejects a *correct* sampler with arbitrarily high confidence at large bin width. ## Analysis-side statistics, validated (2026-09-01)

- **The Block 4 PIT's misalignment control has power again, so the exactness pass is real.** The check `u = CDF_InvGamma(k_L/2+a0, (S_L(φ_i)+b0_L)/2)[C_{L,i}]` is only evidence if a deliberately misaligned pairing is *rejected*, and on job 11903182 the lag-1 control passed at KS_p=0.183 — φ moves so little sweep-to-sweep under the Block-4-ON funnel that `S_L(φ_i) ≈ S_L(φ_{i+1})`, so the test could not see the misalignment it exists to detect, making the aligned pass vacuous. `validate_coverage_rank_nulls.py` now runs the control at several lags (`--control_lags`, default `1,10,50`), prints the measured `corr[S_L(φ_i), S_L(φ_{i+k})]` beside each so the reason a control did or did not bite is visible, and refuses to call the aligned result a pass unless one is rejected at p<1e-3. Measured: lag-1 corr **0.915** → KS_p 0.183 (vacuous); lag-10 corr **0.522** and lag-50 corr **0.086** → both **KS_p = 0**. The aligned statistic (**mean_u 0.4999, KS_p 0.42**, N=17856) is therefore a genuine pass, which is what licenses "Block 4 is exact given φ, so the residual sits in Block 3". Generalises: **the right lag for a misalignment control is set by the conditioning variable's own autocorrelation, so it must be measured, not assumed** — and the control's p-value belongs in the report next to the statistic's.

- **The joint (C_ℓ^TT, C_L^φφ) correlation is a null at the current sample size, and the estimator is built so that is readable as such.** `scripts/plot_joint_cl_clpp_posterior.py` on job 11903182: **1 of 16 bin-pair cells above its permutation null vs 0.8 expected by chance**; strongest cell `C_ℓ^TT [2,10) × C_L^φφ [10,30)`, r = +0.174 against a 95% null of 0.15. Four design choices make that honest rather than deflating: chains are **standardised individually before pooling** (pooling raw draws would measure the cosmic-variance scatter of the 12 truths — a different and much larger quantity than the correlation inside one posterior); thinning is by the run's own τ_int, so the effective sample size is visible (168 pooled draws from 12×600 sweeps); the error bar is a **chain-level** bootstrap, because only the chains are independent, not the sweeps; and significance is against a **within-chain permutation null** rather than zero, because at N_eff≈168 this estimator throws |r| ~ 0.15 on uncorrelated data — the same size as the effect sought. The script prints the implied power: |r|=0.10 at 2σ needs ~2.4× this ensemble, |r|=0.05 needs ~9.5×. A small correlation is also *physically* expected, since `C_ℓ^TT` is the unlensed spectrum and `C_L^φφ` depends on φ alone given φ, the two coupling only through the data via the lensing likelihood. **The null is therefore a statement about sample size, not about physics** — and saying which of the two a null is remains the whole point.

## Real bugs found and fixed (dense-reference validation catches, not derivation trust)

- **φ-block HMC gradient**: a finite-difference backward pass could re-query a shifted angle into a different bilinear-interpolation cell, producing wild step-size-dependent gradients — replaced with an analytic gradient.
- **alm precision convention**: uniform 1/C_ℓ used where the real spherical-harmonic convention requires 2/C_ℓ for m>0.
- **Messenger conditional derivation**: the plausible naive `t|s,d` precision was subtly wrong (needs the reduced noise N−T); caught against an exact dense reference before touching production.
- **SHT operator normalisation**: AᵀA is not a scalar multiple of identity — needs per-mode m=0/m>0 weights *and* empirical calibration (HEALPix quadrature is ~1-2% off the analytic constant).
- **HMC + matrix-free SHT JIT-compile incompatibility**: `jit_compile=True` can't compile through `tf.py_function` — silently never ran until a one-line fix disabled JIT for that path.
- **`tf.gather`/`IndexedSlices` on a custom-gradient output**: `tf.gather` on a `tf.custom_gradient` op's output produces `IndexedSlices`, not a dense tensor, as the upstream cotangent — any `.numpy()`/`tf.py_function` call inside that op's backward pass must `tf.convert_to_tensor()` it first. A second, reverse-direction instance of this same class of bug (the gather's own backward pass being ambiguous, not a downstream consumer) hit the φ-block whitener in 2026-08-18 — see the block-mass-matrix entry above.
- **Cosmic variance mistaken for sampler bias**: an early validation script compared posterior C_ℓ^TT draws against the CAMB *ensemble-average* spectrum, producing spurious multi-sigma "bias" at low l from ordinary cosmic variance. Fixed by comparing against the *realized* power in the actual drawn alm_true instead.
- **`integrated_autocorr_time`'s zero-variance short-circuit was a hidden absolute-tolerance bug**: `np.allclose(x, 0.0)` used a hardcoded `atol=1e-8`, but phi-power summary statistics are naturally O(1e-9)-O(1e-17) — real fluctuations were misread as "no variance" and silently reported as fake ESS=100%. Fixed with a scale-relative check.
- **`lensing.py` never converted author↔healpy alm ordering (found 2026-08-24).** `_alm_packed_to_hp`/`_alm_hp_to_packed` indexed with the *author*-ordering formula `L*(L+1)//2 + m` and handed the result straight to healpy/ducc, which are m-major (`hp.Alm.getidx`). `almmotho`/`almhotmo` — which exist for exactly this conversion, and which `samplers.py::_packed_to_alm_ho`/`_alm_ho_to_packed` do call — were never invoked. `hp.Alm.getidx(127,2,2)=255`; the code wrote that coefficient to index 5. Every coefficient therefore sat at the wrong multipole on the sky: the C_ℓ / C_L^φφ prior that Blocks 1 and 4 apply per multipole was applied to modes living at a different multipole in the likelihood's SHT. Measured effect: packing a `synalm` draw gave `S_ℓ/(2ℓ+1)/C_ℓ` = 1.95 at ℓ=30 (≫5σ); after the fix, 0.90 (σ=0.18), mean 0.972 for ℓ≥30. **Why it survived so long: the wrong index map is a bijection, so `packed→hp→packed` round-trips exactly** — `test_alm_format_round_trip` passed throughout — and `test_compute_sl_phi_np_matches_brute_force_healpy_ordering` hardcoded the *same* wrong formula on its "independent" reference side, so it agreed with the code by construction rather than checking it. Lesson: a round-trip test cannot catch a consistent permutation; only a test pinning an *absolute* (L,m) can. Now covered by `test_alm_hp_to_packed_uses_true_healpy_ordering` (single-mode delta → asserted packed slot) and `test_packed_sl_matches_healpy_power_per_multipole` (exact, non-statistical). φ went through this path in production (`lensing.py` deflection field and `psi_lensed`), and every script built its `alm_true_packed`/`phi_true_packed` "truth" through it, so **all pre-2026-08-24 φ-block results are invalid and must be re-run.** Same-day response: ensemble array `11848757` (running against the broken path) cancelled — tasks 0-5 had already completed and their output (`results/analysis/coverage_ensemble_lmax64/`) must not be used; job `11849969` launched to re-run the plain `phi_mass_matrix='prior'` lmax=64 baseline (identical config to the pre-fix NO-GO job 11752452, worst lag-1 0.975) as the first post-fix data point, since a fixed prior/likelihood ℓ-alignment is the leading candidate explanation for the pathology the Nystrom/Fisher machinery exists to work around.
- **The coverage ensemble cold-started the alm and never ran the pilot's MAP pre-solve (found 2026-08-28, job 11887897).** `scripts/coverage_ensemble_chain.py` built `x0` from an independent prior draw, while `scripts/pilot_coverage_equilibration.py` — the *gate* that cleared the configuration — runs a 2000-step data-driven MAP first. **The gate and the production script were therefore never running the same pipeline**, and all 12 ensemble chains failed: φ and C_L^φφ ranked 0/8 in every ℓ-bin, φ frozen 1.9e3-2.5e5x above the true power. Mechanism, measured not assumed (job 11892269, `scripts/diagnose_phi_amplitude_identifiability.py`, forward evaluations only, no MCMC): with `alm=truth` the lensing likelihood minimises at the true amplitude s=1 (whole-map lensing S/N=67, so φ *is* identified and the model is sound); with the cold-start alm it minimises at **s=30**, because φ becomes the only freedom left to absorb a ~1000x larger residual. Meanwhile Block 4's refitted C_L^φφ makes the φ prior **exactly scale-free** — substituting the conditional mean `S_L/(2(L-1.5))` into the prior gives `0.5·Σ_L S_L/C_L = Σ_L (L-1.5)`, independent of φ; confirmed numerically as **1922.000 at every amplitude from s=0.1 to s=1000**, matching `Σ_{L=2}^{63}(L-1.5)=1922` exactly — so nothing pulls φ back. The chain then freezes (per-step scatter 1.6e-4 at a location 2.2e-2 ⇒ ~1e4 sweeps to diffuse back), which is precisely why it passed a mixing-based gate while being 4-5 orders of magnitude wrong. Corroboration: starts are at the correct φ scale; φ power varies 0.0-3% where ~50% is expected; `logp` drifts monotonically across the whole production window (burn-in never finished); and **corr(alm-vs-truth cosine, log10 φ inflation) = −0.78, p=0.003** across the 12 realizations. **This bug had already been found once** — job 11663105 (2026-07-30) froze the φ block with `phi accept 0.004` for the same reason, which is why the pilot carries a mandatory MAP start *and a warning comment*; the ensemble script simply never inherited it (ensemble realization 002 shows accept 0.008, the same signature). Fixed by giving the ensemble the pilot's MAP start (`--map_steps` default 2000, `--map_lr` 0.01) and `--n_burnin` default 400. **Two lessons, both now in ROADMAP.md's standing discipline: (1) a gate must exercise the production script's own initialisation path — diff their setup before trusting any verdict when gate and production are separate scripts; (2) R̂/ESS/τ_int measure whether a chain is moving, not whether it is in the right place — always also compare a recovered quantity against its known truth scale.** The scale-free property is now pinned by `test_block4_refitted_prior_is_scale_free_in_phi_amplitude` (plus a fixed-spectrum contrast case) so it can never again be mistaken for a prior that regularises the amplitude.
- **Blocks 1 and 4 assumed 2L+1 degrees of freedom per multipole, but the packed parameter vector carries 2L (found and FIXED 2026-08-31).** `model.py::sample_cl_given_alm` and `lensing.py::sample_cl_phiphi_given_phi` both draw from `InvGamma(alpha = L - 0.5, beta = S_L/2)`, whose exponent encodes `(2L+1)/2 - 1`. But the packing drops `Im(a_{L,1})` (only `m>=2` imaginary parts are stored), so **every multipole has 2L real dof, not 2L+1** — verified two ways: `<S_L>/C_true = 2L` exactly, and `S_L/C ~ chi^2_{2L}` in both mean and variance (`k_mean` and `k_var` agree, KS consistent) for the alm packing *and* the phi packing. With `S|C ~ C chi^2_{2L}` the likelihood in C is `C^{-L} exp(-S/2C)`, so for a prior `InvGamma(a0,b0)` the exact conditional is **`InvGamma(L + a0, b0 + S_L/2)`** — i.e. `alpha = L - 1` under the flat prior (`a0 = -1`), not `L - 0.5`. Confirmed by direct SBC scan over the exponent: offset 0 (correct) gives `mean_u = 0.5029, KS_p = 0.075` at N=4000, while the code's convention is rejected at `KS_p = 1.5e-21` and an `L-1+nu/2` variant at `2.5e-79`. **Size of the error:** `E[C_L]` is wrong by `(L-1.5)/(L-2)` — 0.8% at L=63, 1.8% at L=30, 6% at L=10, **50% at L=3, and at L=2 the correct posterior mean does not exist** (`alpha-1 = 0`), so the bias is concentrated exactly at low L where cosmic variance is largest and where the project's φ problems have always shown up. **Why it survived every previous check:** the 2026-08-31 PIT test (`u = CDF_InvGamma(L-0.5, S_L/2)[C_L]`, KS_p=0.53, N=17856) asks whether the draws match *the same formula the code uses* — a self-consistency test, structurally incapable of detecting a wrong exponent. Under the flat improper prior no strict SBC exists for the spectra at all, so nothing else could catch it either. **It took the proper-prior run (Option 2, job 11900610) to expose it**, because a proper prior is what makes a strict `C_L^phiphi` SBC rank possible: that rank came back `mean_u = 0.25-0.28, KS_p = 0.0000`, robust to thinning, which is what led to the isolated Block-4-only test and then the dof count. Lesson, and it generalises: **a probability-integral-transform check against the sampler's own stated conditional validates the draw, not the derivation** — to test the derivation you need an independent generative draw, which in turn needs a proper prior. **Fixed** by deriving the shape from the packing itself (`alm_utils.packed_dof_per_multipole` / `invgamma_shape_for_spectrum`, `alpha = k_L/2 + a0`) rather than hardcoding it, so both conditionals stay correct if the missing dof is ever restored. Knock-on caught at the same time: the proper prior's properness threshold is **nu > 0, not nu > 2** (the tail is `r^(-1-nu)` once `k_L` cancels) — a threshold derived alongside a wrong exponent inherits its error. Now guarded by `test_block4_conditional_passes_an_independent_generative_sbc`, verified by mutation to fail under the 2L+1 assumption; two earlier tests that encoded the old convention were re-derived rather than relaxed. **Post-fix verification (job 11903182, harvested 2026-08-31): necessary but not sufficient.** The strict `C_L^φφ` SBC rank that exposed the bug moved from `0.25-0.28, KS_p = 0.0000` to **`0.3802, KS_p = 0.0013`** — a large, real improvement that confirms the fix, but it does **not** clear. The residual is not burn-in (flat at 0.400 on the 2nd half, 0.396 on the last quarter) and is not Block 4's conditional (its PIT given φ is `mean_u 0.4999, KS_p 0.42`); it tracks a φ over-power of median 1.08-1.14 concentrated in the same `[10,30)` bin as the φ field-rank deficit (0.292), so it points at **Block 3 / mixing under the Block-4-ON funnel** (τ_int median 24-56 vs 4.7-27 with Block 4 off; split-R̂ max 1.64 vs 1.31). Open in `ROADMAP.md`.
- **The dof fix landed in the samplers but not in the two analysis scripts that mirror the same derivation (found and FIXED 2026-08-31, immediately after the fix above).** `model.py`/`lensing.py` were corrected to derive `alpha` from the packing, but `aggregate_coverage_ranks.py::realized_spectrum` still divided `S_l` by `2l+1`, and `validate_coverage_rank_nulls.py` still hardcoded `alpha = L - 0.5` in **all three** of its checks (frozen-field null, φ-trajectory null, and the Block 4 PIT). So the first harvest of the relaunched ensembles compared corrected chains against a stale reference on both sides at once. This mattered doubly because `realized_spectrum` is not just a convenience: it *is* the coverage reference, and the entire "the statistic ranks the truth against its own conditional's mode" argument identifies it with `beta/(alpha+1)`, which under the corrected shape is `S_l/k_l = S_l/2l`. The validator was additionally wrong on a second axis — it assumed a flat prior everywhere, so its null and PIT were incorrect for the proper-prior ensemble regardless of dof. **Fixed** by deriving from `packed_dof_per_multipole`/`invgamma_shape_for_spectrum` and, in the validator, reading both the shape **and** the prior `(a0, b0)` off the saved chain (`prior_of`/`alpha_of`) so a null can no longer drift from the configuration it validates; it also now skips the Block 4 check on Block-4-off chains rather than raising `KeyError`. Effect on the numbers was modest but real (e.g. job 11903181 `C_l^TT` pooled 0.133 → 0.148) and did not change any verdict. **Lesson, and this was the third instance of the same slip in one week: fixing a derived constant in the sampler is not done until every script that re-implements the derivation is fixed too.** A null, a reference value, or a PIT that restates a conditional is inside that conditional's blast radius — grep for the old constant across `scripts/` as part of the fix, not after the next harvest looks odd.
- **`run_gibbs_chain(seed=...)` never seeded the HMC (found 2026-08-31).** `seed` built `np.random.default_rng(seed)` for the numpy-side draws (Blocks 1 and 4, mass-matrix probes, CG/messenger noise) and threaded it everywhere — but none of the five `one_step` calls pass a `seed=`, so TFP took every HMC/NUTS momentum and Metropolis uniform from TensorFlow's **process-global** RNG stream. A nominally seeded chain therefore depended on how many TF random ops had already run in the same process. Measured directly: consuming 5 `tf.random.normal` draws before an otherwise identical `seed=7` chain moved the recovered `C_L^φφ` by 5x (4.12e-7 → 8.32e-8). This is what made `test_gibbs_chain_sample_cl_phiphi_recovers_known_spectrum` pass in isolation and fail in a full-suite run — it was **never flaky, it was reading an unseeded stream**, and the file's own `tf.random.set_seed` calls elsewhere show the global stream was already known to matter. Fixed by seeding the global stream inside `run_gibbs_chain`; pinned by `test_gibbs_chain_seed_is_immune_to_prior_global_tf_rng_state`, which asserts **bit-identity** (`rtol=atol=0`) across a chain run before and after deliberately advancing TF's RNG, and which was confirmed to fail with the fix disabled. Does not invalidate job 11899585: the numpy side was correctly seeded, so the 12 realizations still had independent, properly drawn data. Lesson: a `seed=` argument that only covers *one* of two RNG backends is worse than none, because it advertises reproducibility the chain doesn't have — and an intermittent test failure is a hypothesis to chase, not a flake to tolerate.
- **Two stale method claims in `docs/paper/main.tex` (found and fixed 2026-09-01).** (i) Block 3 was described as sampling φ with **MCLMC**, citing the one-to-three-order-of-magnitude efficiency gains reported for it on curved-sky CMB fields. MCLMC was in fact implemented against this target and **fails the stationarity gate twice** — untuned and step-size-tuned, with the tuned nside=128 run's lag-1 autocorrelation *worse* than untuned (≈1.000 vs ≈0.975-0.99). Production is and has been plain HMC with a long trajectory. The section now says so and records the negative result, including the generalisable point: MCLMC wins ESS per wall-clock second at every probed bin, so **an efficiency metric that ignores whether the chain is stationary selects the wrong sampler here.** (ii) The demonstrated scale was quoted as `lmax ≈ 128` in three places; 128 is where chains have been *run*, 64 is where the calibration test *passes*. Corrected, with the "demonstrated beats asserted" reasoning stated in the scope paragraph rather than left implicit. Lesson: a paper drifts from the code most easily where it describes a route that was *planned* and then abandoned — the plan gets written once and the abandonment gets recorded only in the notes.
- **A number in `docs/paper/main.tex` had migrated to a claim it never supported (found 2026-09-01).** The §"what the deficit is not" paragraph attributed the φ-amplitude deficit to under-mixing and cited "ρ = −0.78 across 27 multipole bins" as evidence that it decreases with signal-to-noise. That ρ is the 2026-08-28 diagnostic `corr(alm-vs-truth cosine, log10 φ inflation) = −0.78, p=0.003` across the **12 realizations** of the *cold-start* ensemble — a different quantity, a different sample, and a failure that has since been root-caused and fixed by the MAP warm start. Rewritten to state the cold-start mechanism it actually measures. Lesson: when a diagnostic number is promoted from a harvest note into prose, re-derive what it is a correlation *of* — a statistic carried across contexts keeps its digits and loses its meaning.
- **`run_gibbs_chain`'s return-tuple arity depends on which blocks are enabled** (4-tuple with no φ block, 5-tuple with φ, 6-tuple with φ+C_L^φφ) — a script hardcoded a 5-tuple unpack for a no-φ-block call, crashing *after* a full 3000-sweep chain completed. SLURM reported `COMPLETED, exit 0:0` since the traceback was inside Python after the job's own work was done — always check `.err` for a traceback, not just SLURM job state, when harvesting completed jobs.

## Closed-out sampler routes (do not revisit without new evidence)

- **Diagonally-preconditioned CG on the masked sky: abandoned.** Jacobi preconditioner degrades ~4 orders of magnitude under a realistic mask; extrapolated cost 10⁴-10⁵ iterations per Gibbs step.
- **Messenger-field sampler: built, validated at small scale, closed as non-viable at production scale.** Conditionals correct against dense references, but the production run showed intrinsic critical slowing down at n_alm≈90k (ESS 0.6%, C_ℓ biased low, monotonic drift). Superseded by the HMC + matrix-free-SHT pivot above.
- **Unlensed-operator exact Block-2 shortcut for alm|C_ℓ: rejected** (Phase 2 pre-production gates above). Not fundamentally dead — a CG solve built from autodiff of the lensed posterior could target the correct conditional exactly — but unexplored and not worth pursuing unless HMC-on-both-blocks becomes a proven throughput bottleneck.

## Engineering gotchas worth remembering

- **Eager-mode `tf.py_function` calls in a hot loop leak memory** — wrap in `@tf.function` instead. A value that must reach a traced function and changes between calls must be a `tf.Variable` read via `tf.convert_to_tensor`, not a plain Python/numpy value closed over — the latter gets silently baked into the trace as a constant.
- **`/cosma/apps/durham/dc-hick2` has its own NFS quota** (100GB / 10M files, `quota -s` not `lfs quota`) shared across all of dc-hick2's project directories, not just diffcmb.
- **`/cosma5` is NOT mounted on `dine2`/`cosma7`/`cosma8` compute nodes — only on the login node.** A symlink pointing there loads fine from the login node but is silently invisible to `os.path.exists()` inside an sbatch job. Always verify a checkpoint-path fix with `srun -p <partition> python3 -c "np.load(...)"` on the actual compute partition.
- **Write large per-run artifacts to `/cosma8/data/dp004/dc-hick2/diffcmb_results_archive/` and symlink back into the repo's `results/` tree** — confirmed mounted on `dine2` compute nodes, this project's established archive location. Don't write in-place under `/cosma/apps` (quota risk above) and don't use `/cosma5` (not mounted on compute nodes). Distinct from the `/cosma8` dp004 *space* quota (global `~/.claude/CLAUDE.md`) — a headroom concern for large campaigns, not a mount-visibility problem.
- **SLURM `COMPLETED`/exit-0 does not mean the Python script's own logic succeeded** — always check the `.err` file for a traceback even on a clean SLURM exit.
- **dine2/cosma8 reused nodes need a job-private `$TMPDIR`** (autograph cache collision) — every pilot sbatch script sets this.
